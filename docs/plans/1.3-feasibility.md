# 1.3 feasibility — lazy tool schemas & the Hermes Agent upgrade (2026-09-09)

Read-only investigations; nothing in `~/.hermes/hermes-agent` was patched. Sources: `research/13-feasibility.md` (A), `research/13-feasibility-B.md` (B), `research/124-routing-map.md` + `docs/plans/routing-v2-deferred.md` (drill context), `docs/plans/1.2-baseline.md` "Prompt budget" (measured baseline).

## 1. Decision summary

**(a) Prompt-diet phase 2 — recommend the plugin (`tool-schema-diet`).** The `llm_request` middleware rewrites `request["tools"]` per call today, no fork; `registry.dispatch()` doesn't require a tool to have been in the last request's tool list, so compact-catalog + on-demand-expand is mechanically sound. Propose the small upstream patch (relax `_HERMES_CORE_TOOLS`) in parallel — more durable but merge-dependent, don't block on it. Fallback: stop at the 31% config ceiling (Focused) if the plugin's savings don't clear measurement.

**(b) Hermes Agent upgrade — attempt in a sandbox, gated by the agent drill.** 0.18.0→0.21.1 is three minor versions / 18,719 commits, zero local fork commits to lose. Stand up sandbox `HERMES_HOME` + `hermes serve --port 9129`, run the drill (§4) against both runtimes, decide cutover only after. Never touch the live install first.

## 2. Lazy / compact schemas — what is possible

**Hooks can't reshape tools; a middleware can.** `VALID_HOOKS` (`hermes_cli/plugins.py:135-208`) has no hook that sees/rewrites `tools=`: `pre_llm_call` fires once per turn with no `tools` kwarg (`agent/turn_context.py:434-456`), only injects text into the user message; `pre_api_request`/`post_api_request` (`agent/conversation_loop.py:1107-1149, 4105-4125`) get only `tool_count`, and their return value is discarded (bare `try/except: pass`). The working mechanism: `ctx.register_middleware( "llm_request", cb)` (`hermes_cli/plugins.py:1128-1141`, `hermes_cli/middleware.py`) sees the full `api_kwargs` — including the real `tools=` from `agent/chat_completion_helpers.py:606-645` — right before send (`conversation_loop.py:1101-1120`) and may return a replacement request.

**Registry check keeps hidden tools callable.** `model_tools.py`'s `handle_function_call()` (`:904-1080`) never validates `function_name` against the last request's tools; a direct call reaches `registry.dispatch()` (`tools/registry.py:574,265`), checked against the global registry, not the last request's schema. Only `tool_search`'s defense-in-depth (`model_tools.py:989-1005`) enforces session-scoping — a plugin hiding schemas while leaving tools registered would not be rejected on an out-of-catalog call.

**Native tool_search is core-tool-exempt.** `tools/tool_search.py` already ships compact-catalog-plus-expand (`tool_search`/`tool_describe`/`tool_call` bridge tools), but `_HERMES_CORE_TOOLS` (`toolsets.py:31-80`) are never deferred by design (`tool_search.py:9-11,163-183`) — `session_search`, `terminal`, `delegate_task`, `skill_manage`, `computer_use` are all core, permanently exempt. The shipped mechanism cannot touch the ~15.5k tokens targeted here.

**Description share, measured:**

| Tool | Total B | Desc B | Desc % |
|---|---|---|---|
| session_search | 5,826 | 5,180 | 88.9% |
| terminal | 5,536 | 4,930 | 89.1% |
| delegate_task (dynamic) | 5,518 | 4,849 | 87.9% |
| computer_use | 5,109 | 3,346 | 65.5% |
| skill_manage | 4,066 | 3,329 | 81.9% |

No `schema_level`/`compact_description`/`verbosity` switch exists in `toolsets.py`, `tools/registry.py`, `model_tools.py`, `hermes_cli/config.py`.

**Three ranked options** (effort / upgrade-fragility):
1. **Plugin-only**: `llm_request` rewrites `tools=` to a compact catalog + one meta-tool, resolves real tools via `ctx.register_tool`/`pre_tool_call`. Works today, no fork. Moderate fragility — reimplements guardrails `tool_search.py` already has, tracks drift vs. the live registry.
2. **Minimal upstream patch**: relax `_HERMES_CORE_TOOLS` via an opt-in `tool_search.defer_core_tools` key, or add `schema_level` at `classify_tools()`/`assemble_tool_defs()` (`tool_search.py:189-206, 529-577`). ~10-30 lines, near-zero fragility once merged, most upstream-friendly, but merge-dependent.
3. **Config-only**: none found beyond the already-shipped ~31% Focused ceiling — no key inverts core-tool exemption or adds a verbosity switch.

**Savings beyond ~31% are estimates.** Focused (`1.2-baseline.md`): 33→19 tools, 55,099 B → 31,263 B, ~14,521 tokens, ~19.4 s first token, 31.3% saved. The description-share table suggests a compact-schema plugin could cut the 4 biggest tools' description text substantially, but no end-to-end token count exists for it yet — confirm with `hermes prompt-size --platform tui --json` plus `GET /api/prompt/budget` before quoting a number.

## 3. Upgrade in a sandbox — the recipe

**Version gap, confirmed clean.** Local checkout: shallow-clone pin at `19d4174454` (PR #57685, 2026-07-03) = `0.18.0`, zero local fork commits (`git rev-list --left-right --count HEAD...origin/main` = `0 18719` after `git fetch --unshallow`). Newest tag `v2026.9.7` (`0.21.1`, `2237be3`, 2026-09-07). Only local drift: incidental `package-lock.json` diff, untracked `.install_method` marker.

**Command sequence** (clone/venv outside `~/.hermes`, per `CONTRIBUTING.md:144-172`):

```bash
git clone https://github.com/NousResearch/hermes-agent.git ~/scratch/hermes-agent-sandbox
cd ~/scratch/hermes-agent-sandbox && git checkout v2026.9.7
uv venv ~/.hermes/venvs/hermes-dev-sandbox --python 3.11 && export VIRTUAL_ENV="$HOME/.hermes/venvs/hermes-dev-sandbox" PATH="$VIRTUAL_ENV/bin:$PATH"
uv pip install -e ".[all,dev]"
export HERMES_HOME=~/scratch/hermes-home; mkdir -p "$HERMES_HOME"/{cron,sessions,logs,memories,skills,plugins}
cp ~/.hermes/config.yaml "$HERMES_HOME/config.yaml"      # redact secrets first
cp -R ~/.hermes/skills/* "$HERMES_HOME/skills/"          # copy, not symlink
ln -s ~/HermesAssistant/hermes-plugins/tool-budget "$HERMES_HOME/plugins/tool-budget"
touch "$HERMES_HOME/.env"                                # or a redacted subset
HERMES_HOME="$HERMES_HOME" HERMES_DASHBOARD_SESSION_TOKEN=<own-token> "$VIRTUAL_ENV/bin/hermes" serve --port 9129 --skip-build
```

**State under HERMES_HOME**: `ensure_hermes_home()` (`hermes_cli/config.py:842-873`) — `cron`, `sessions`, `logs`, `logs/curator`, `memories`, `pairing`, `hooks`, `image_cache`, `audio_cache`, `skills`, `SOUL.md`; `state.db` (`hermes_state.py:123`). Live `~/.hermes` also has `config.yaml`, `.env`, `auth.json`/`auth.lock`, `plugins/`, `mcp-allow.json`, `mcp-tokens/`, `dashboard/` (HermesAssistant-owned), `bench/`, `cache/`, `checkpoints/`, `metrics/`, `kanban.db`.

**Hazards.** Never run `hermes serve --stop`/`--status` from the sandbox — no PID file, no port/home scoping: they scan the process table for `hermes dashboard`/`hermes serve` cmdlines and SIGTERM them (`hermes_cli/subcommands/dashboard.py:68-73`); `--stop` from the sandbox would kill the LIVE `com.hermes.serve` too. Kill the sandbox's own PID directly instead. Unset `HERMES_DASHBOARD_SESSION_TOKEN` gives a fresh random token per process, no collision with the live token file; use `--port 9129` vs. the live default `9119`. Shared model lanes are fine: `config.yaml`'s `base_url`s point at the shared MLX servers (`:8080`/`:8081`) — shared inference capacity, not a state collision. `.env` holds live secrets — redact before copying into the scratch home.

**One dashboard test session reaching the sandbox.** No dashboard change is needed to start the sandbox server. `dashboard/hermes_rpc.py:22-25` has an env override, `HERMES_SERVE_PORT` (default `9119`), but `TOKEN_FILE` (`~/.hermes/dashboard/serve-token`) is hardcoded. Lowest-risk: a **standalone throwaway Python driver reusing `hermes_rpc`'s `WSClient` directly** — set `HERMES_SERVE_PORT=9129`, a scratch token path, never touch `dashboard/server.py`/`hermes_rpc.py`. `run_agent()` (`dashboard/server.py:974-1005`, the `hermes -z` path) has no `HERMES_HOME`/binary override at all — out of scope for a first test.

**Not checked — the breaking-change survey.** No CHANGELOG in the repo; 18,719 commits between the two points. Survey before cutover: `tui_gateway` RPC (`session.create`, `prompt.submit`, `status.update`, `session.branch` — whether a model/lane override field was added); plugin hooks (`transform_tool_result`, `pre_llm_call`, the `llm_request` middleware contract this plan depends on); `platform_toolsets` resolution (the hardcoded `cli` key `1.2-baseline.md` relies on); `compression.*` semantics (threshold/target_ratio/protect_last_n/protect_first_n); memory files (`MEMORY.md`/`USER.md` format, `memory_tool.py` snapshot); `prompt-size` CLI output shape (the prompt-budget card parses it); `hermes serve` flags (`--skip-build`, `--port`, `--stop`/`--status`). Next step: `git log 19d4174..2237be3 --oneline -- 'gateway/*' 'plugins/*' 'agent/*'` filtered on the above, plus `git show <tag> --stat` per tag.

## 4. The agent drill (the gate both decisions need)

Needs the model running (AC only). The existing eval suite (`aux_evals.py`, 9 cases) is **model-direct** — posts straight to `/v1/chat/completions` with a synthetic 3-tool schema, no agent, no tool execution, no approvals, no Flight Recorder rows — it does not cover the agent loop this drill needs.

1. Read a known file — pass if content echoed exactly. Flight Recorder / `state.db` tool_calls.
2. Write a temp file, undo via Flight Recorder — pass if restored + a recorder entry exists. recorder.db.actions.
3. Trigger `web_search` — pass if a `tool.start`/`tool.complete` event appears. `state.db` tool_calls / `/api/console`.
4. Memory write — pass if the memory file gains the new fact. File diff.
5. Ask something requiring clarification — pass if the turn ends in a question, not a guess. `/api/history`.
6. Delegate to a sub-agent — pass if a child session_id links to the parent. `state.db` session table.
7. Read a large file to trigger tool-budget truncation — pass if truncated/spilled per contract. `tool-budget.jsonl` + `transform_tool_result` firing.
8. Long multi-turn conversation to trigger compaction — pass if a compression/summary event appears. Context meter (`/api/context/turn`, `compacted: true`).
9. Destructive-looking shell command — pass if `approval.request` fires and the turn blocks until `approval.respond`. `/api/console` / Flight Recorder.
10. Control turn ("reply with exactly: ok") — pass if byte-identical, a regression canary. `/api/history` diff.

Run identically against live (0.18.0) and sandbox (0.21.1), diffing pass/fail and latency (metrics JSONL `kind:"turn"`). Drafted from task framing, not validated against `aux_evals.py`'s actual harness API — spot-check once `dashboard/aux_evals.py`, `docs/plans/p1-4-approval-loop-test.md` and `tools/bench` are read.
